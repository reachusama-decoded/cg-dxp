1 · What is AI Catalyst?

Catalyst is the unified AI layer across Capital Group's data platform stack: purpose-built agents and skills, the standard Data Product Lifecycle (RFD 0002), and a set of architectural defaults, delivered as a plugin inside your coding agent.

By architectural defaults we mean this: Capital Group's data architecture standards and the Enterprise Data Office's (EDO) practices are packaged into the skills themselves, so two teams building two data products arrive at the same shape without having to negotiate it each time. The plugin is the interface; the value is the operating model — governed by default, instrumented from day one.

Three pillars: AI Catalyst (agents, skills, playbooks), Marketplace (governed discovery and publishing), and the Paved Path (Databricks, dbt/PySpark, Harness CI/CD, Airflow, repo templates).

Official landing page: AI Catalyst in the ENTDATA Confluence space — onboarding, release notes, roadmap, and the calendar all hang off it. For the wider program context, see the Data Excellence Platform (DxP) SharePoint site. In this repo, start with the skills graph (all 103 skills and how they connect) or the DPLC skill architecture.

3 · Who is it for?

Do I have to be a Data Product Creator (DPC) to use it?

No. Catalyst is designed around the DPLC and is aimed at practitioners certified through the Data Product Creator Program, but many people use the skills for adjacent work — document generation, research synthesis, planning, dashboards, and prototypes. If you are not building a data product, you can still install the plugin and use the document and capability skills.

If you are building a data product, get certified — certification is how teams stay aligned on the same lifecycle and quality bar. Contact DxP_Data_Creator_General@capgroup.com to join the training program.

I'm not technical. Is this going to work for me?

Yes, with a caveat: the setup is more technical than Microsoft 365 Copilot, even though using it afterwards is mostly conversational. Budget roughly 30–45 minutes for first-time setup, plus 1–2 business days waiting on access approval.

If you have never used VS Code or GitHub, start with 0 Pre-Req: Setting Up VS Code GitHub Copilot in Confluence. It starts where you need to start — requesting the GitHub EMU All Users role in Access Central, which needs manager approval and takes 1–2 business days — and walks the rest of the setup from there. Pair it with the GitHub Copilot Self-Service guide on DevHub for the install and sign-in steps.

4 · How do I get started? — prerequisites

Work through these in order. Skipping a prerequisite is the single most common cause of "the skills don't show up."

Once the plugin is running, let it check the rest for you

From step 5 onward you don't have to audit your own machine. Ask for dplc-preflight — or just say "am I set up?", "which workspace am I in?", or "nothing works". It reports whether you can run Catalyst at all, every Databricks workspace configured on your machine (not just the one you think you're using), whether you actually have access, and which catalogs you can see — then points at the skill that fixes whatever is missing. It is read-only and degrades rather than crashing, so it still works on a half-configured machine.

Q: Where do I start if I have nothing installed?

Access Central first. You need the GitHub EMU All Users role before GitHub Copilot can be provisioned for you, and it requires manager approval (1–2 business days). Request it, then keep going — you can install VS Code, Git, and Python and configure Git while you wait. Only the Copilot step is blocked.

Q: How do I install VS Code, Git, and Python?

Follow 0 Pre-Req: Setting Up VS Code GitHub Copilot — the maintained setup page in the AI Catalyst onboarding path, covering both platforms.

  • macOS: VS Code and Python from Self Service. Git ships with macOS; if it's missing, typing git in Terminal prompts the install.
  • Windows: VS Code, Git, and Python from the CG App Store — plus the Developer Tooling Network Certificates package, which is Windows-only and required for pip installs and API calls to work behind the corporate proxy. Skip it and installs fail in ways that look like network errors. Budget a few hours for App Store installs to land before you continue.
  • Python version: 3.10 is the minimum and 3.13 is recommended — 3.13 is the only Python currently receiving both bug-fix and security backports. Python 3.9 will not work: it is past end-of-life, and pip install -r skills/requirements.txt fails on it because markitdown no longer ships 3.9 wheels.
  • VS Code version: 1.90 or newer.

Verify in the VS Code terminal (Ctrl + `): git --version and python --version should both print a version. For VS Code itself use Help → About — running code --version in the integrated terminal can open a new VS Code window instead of printing the version. If anything says "not found," redo that install.

Q: Why do I need a GitHub Personal Access Token?

SSH is blocked on the corporate network, so Git must authenticate over HTTPS. Two ways, both in 0 Pre-Req → Git HTTPS Setup:

  • Recommended — let the GitHub CLI do it. Install gh (brew install gh on macOS; on Windows winget often fails on the corporate network, so the setup page gives you a Copilot Chat prompt to walk it through), then run gh auth login → GitHub.com → HTTPS → browser. Git is configured and your credentials are stored for you.
  • Manual. Set user.name / user.email, enable a credential helper (osxkeychain on macOS, manager on Windows), then create a token at github.com/settings/personal-access-tokens/new. For a fine-grained token, grant Contents: Read and write and limit it to the repos you need; a classic token needs the repo scope — that is all HTTPS clone and push needs. Do not add write:org: it grants organisation management this setup never uses. Set a 90-day expiry, and copy the token before you leave the page — it is shown once. On the first push or pull, enter your GitHub username and paste the token as the password.

Your GitHub username is INITIALS_capgroup and your email is initials@capgroup.com. PATs expire every 90 days — when Git suddenly stops working, this is usually why.

Q: Which tool connections do I need?

Only the ones a skill actually needs. Most document-generation and planning skills work with no connection at all — they still run, they just ask you for context that would otherwise come from a live system. Set a connection up when you hit a skill that queries Unity Catalog, or reads and writes Confluence/Jira.

Easiest route: paste this into Copilot Chat and be walked through it — no terminal experience needed (per the Tool Connection Guides):

Help me set up my tool connections. Walk me through it step by step.

Or do it by hand. Each system has its own guide in Confluence:

Which Databricks setup you need depends on what you're doing. Catalyst reaches Databricks three ways, and they are not interchangeable:

  • The Databricks SDK — the default for workspace API calls. It reads credentials from, in priority order, OAuth service-principal env vars, an explicit host/token, DATABRICKS_HOST/DATABRICKS_TOKEN, then a ~/.databrickscfg profile.
  • The Databricks CLI — a hard requirement for roughly ten Build and Ship skills (bundles, jobs, deployments), not merely a convenience. It is also the easiest way to populate the credential store the SDK then reads. Note it is a Go binary: install it from the official release, not from PyPI, where the old databricks-cli package stops at 0.18.0 and is a different tool.
  • A SQL warehouse endpoint — separate from credentials, and identified by DATABRICKS_WAREHOUSE_ID (or an http_path). Being authenticated does not give you somewhere to run SQL. discover-data needs a warehouse id for schema verification, alongside OAuth service-principal credentials; connect-databricks sets it up, and configure-sql-warehouse provisions a serverless warehouse and wires http_path and warehouse_id into profiles.yml when you are pointing dbt at Databricks.

So "I have a token in .env" is enough for some exploration, and not enough for building, shipping, or dbt.

If you are…You need
Exploring and profiling data, or generating documents — discover-data, data-profiling, query-table, query-catalog, profile-columns .env with DATABRICKS_HOST and DATABRICKS_TOKEN is enough
Building or shipping — anything touching Asset Bundles, jobs, SQL warehouses, or dbt-on-Databricks: deploy-dab, databricks-bundles, databricks-jobs, configure-sql-warehouse, run-dbt-on-databricks, setup-databricks-asset-bundle The CLI binary, installed. These shell out to databricks bundle …; .env credentials alone will not satisfy them

So if you are walking the full lifecycle, install the CLI and authenticate with databricks auth login --host <your-workspace>. That writes a profile to ~/.databrickscfg, which the SDK, the VS Code extension, dbt, and the CLI itself all read — one setup covers every route. Verify with databricks catalogs list. Prefer OAuth over a Personal Access Token: DBX-SEC-002 asks for it, and /connect-databricks refuses a DATABRICKS_TOKEN outright, so the PAT route will stop you at the first skill that checks. Catalyst targets the Databricks CLI 0.218 or newer — the Go binary, installed with brew install databricks or winget install Databricks.DatabricksCLI. Not a pip install: the PyPI package called databricks-cli is the deprecated legacy Python CLI and stops at 0.18.0.

The .env route stays useful where the CLI cannot be installed, and is the right answer for non-interactive contexts — CI, or a Databricks App using OAuth service-principal credentials. Note that docs/install.md and README.md now document the CLI and the OAuth login alongside .env, which is what closes the gap where a user got discovery working and then hit a wall at the first bundle deploy (AICAT-322).

The variable-by-variable walkthrough for the .env route is in docs/install.md.

Dremio is not supported by Catalyst. Confluence still carries a Dremio connection guide under Tool Connection Guides; it describes legacy infrastructure that this project does not support, and it promises a dremio-query skill that does not exist here. Ignore it. Databricks and Unity Catalog are the supported platform surface.

Python installs must go through the internal mirror

Public PyPI is blocked on the corporate network to mitigate supply-chain attacks. skills/requirements.txt already pins the internal Nexus mirror via --index-url. If pip returns a 404 or a timeout against pypi.org, that is the network block firing — not a missing package. Re-point pip at https://cgrepo-aws.capgroup.com/repository/cgpypi/simple/. The same applies to npm, Docker, Maven, conda, and NuGet — see Internal artifact registries.

Q: What about Claude Code and DevNext/Coder?

These are a parallel path, not a replacement.

  • Claude Code is the Anthropic coding agent. Catalyst skills are authored in a format that works across both the Copilot and Claude Code harnesses. On a DevNext/Coder workspace it is already installed — it ships in the image, so there is nothing to install and no npm command to run. Confirm with: 
    claude --version
    Then install the Catalyst plugin into it via Path C.
  • DevNext / Coder is the managed cloud development workspace where dev tools and AI agents run — reachable from VS Code, JetBrains, browsers, terminals, and SSH. Workspaces are disposable by design: your home folder persists, everything else is rebuilt. Source of truth lives in GitHub, not in your workspace.
  • Access to Coder and Claude is provisioned by DevNext in waves, not self-service. If your team hasn't been deployed yet, use the local VS Code + Copilot path.

Rule of thumb: if you already have VS Code + Copilot working locally, that is the fastest route to Catalyst today. Catalyst runs on Claude Code as well, so if you already have a Coder workspace you can use it now — the gating factor is DevNext access, not Catalyst support.

You don't install Claude Code — GT does

Claude Code is available only on DevNext/Coder workspaces, where it ships in the image and the GT team manages it end to end: installing it, upgrading it, and keeping the version consistent across workspaces. There is no self-service route and no supported way to add it to a personal machine.

So there is nothing for you to install, and installing your own copy would actively hurt: Coder persists your home directory and rebuilds everything else, so a private copy there would take precedence on PATH and keep shadowing the managed version after every rebuild. If claude --version answers, you are done. If it doesn't, that is a DevNext question, not a setup step.

5 · Installing and updating the Catalyst plugin

Q: How do I install it?

The canonical, maintained steps are in docs/install.md — follow that, or the Confluence Installation: AI Catalyst Skills page, rather than reusing an older set of instructions. The short version, for most users: add the marketplace to your VS Code user settings (Ctrl+Shift+P / ⌘⇧P → Preferences: Open User Settings (JSON)):

{
  "chat.plugins.enabled": true,
  "chat.useAgentSkills": true,
  "chat.plugins.marketplaces": [
    "https://github.com/cg-open-itg/catalyst.git"
  ]
}

Reload VS Code, open Copilot Chat (Ctrl+Shift+I / ⌘⇧I) → /plugins → enable AI Catalyst. No clone required. Contributors who want to edit skills should use Path B in the install guide instead.

Q: How do I install it on Claude Code?

The same repo is also a Claude Code plugin marketplace (Path C). Register it once, then install the plugin:

claude plugin marketplace add cg-open-itg/catalyst
claude plugin install ai-catalyst@catalyst

Or from inside a session: /plugin marketplace add cg-open-itg/catalyst then /plugin install ai-catalyst@catalyst. Nothing to configure in settings.json — Claude Code discovers skills/<name>/SKILL.md on its own, which is why there is no marketplace block to paste here.

Opening this repo in Claude Code registers and enables the plugin for you, because it ships that registration in its own .claude/settings.json — the Claude Code counterpart of Path B. One caveat worth knowing: that resolves from published main, not your working tree. If you are editing a skill locally, point the marketplace at your checkout instead (claude plugin marketplace add /path/to/catalyst) or you will be testing published code rather than your edits.

Q: I installed it but no skills appear.

  • Reload the window first: Ctrl+Shift+P / ⌘⇧P → Developer: Reload Window.
  • Confirm chat.plugins.enabled is in your user settings, not workspace settings.
  • Confirm you are signed in to your GitHub account inside VS Code — authentication failures surface as missing or broken skills.
  • Getting an SSO redirect or a 403 when the marketplace tries to clone? Your GitHub credentials need to be authorized for the cg-open-itg org. The install guide's troubleshooting section has the three commands that fix it.
  • Still nothing? Reinstall. An early defect caused skills not to load after install; it has since been fixed.
  • On Claude Code the checks are different — none of the chat.* settings apply. Confirm the marketplace is registered (claude plugin marketplace list) and the plugin is installed and enabled (claude plugin list), then see Plugin doesn't appear in Claude Code.

Q: How do I get the latest version?

No reinstall needed, and no version pinning — you track main. Do any one of these:

  • Reload the window — Ctrl+Shift+P / ⌘⇧P → Developer: Reload Window
  • Click the refresh icon (circular arrow) in the Agent Plugins panel
  • Restart VS Code — quit and reopen

If a release you expect still isn't there, force it from Extensions: the […] menu → Check for Extension Updates. You should see an "updated plugins…" message.

On Claude Code updating is explicit rather than reload-triggered — refresh the registry, then update the plugin:

claude plugin marketplace update catalyst
claude plugin update ai-catalyst@catalyst

To pin a release instead of tracking main, append the tag to the marketplace ref (claude plugin marketplace add cg-open-itg/catalyst@1.12.0). Tags here are unprefixed — 1.12.0, not v1.12.0.

You may also see the claim that the plugin self-updates about 24 hours after a release, on Updating AI Catalyst Plugin. Treat that page as the outlier: three other sources — Confluence How To: Give Feedback, docs/install.md, and the boilerplate on every release comms page — all describe a reload-triggered refresh with no waiting period. Don't wait a day; reload.

6 · Your first five minutes with Catalyst

Q: I'm in. What do I run first?

Run the concierge. If you don't know which skill to invoke, start with dplc-concierge — the entry-point router that detects your intent and points you at the right phase orchestrator. This is the answer to almost every "which skill do I need?" question, and it's why this FAQ stops here.

You don't have to name skills. Type what you need and Copilot matches it. To confirm the install works, try:

I need to plan a new data product

Copilot should route to dplc-concierge and reply with orienting questions.

Q: What if I'm not doing DPLC work?

Browse the skills graph or skills/README.md. Skills come in four tiers, and two of them are useful whether or not you're building a data product:

TierWhat it does
OrchestratorsGuide you through a whole lifecycle stage or phase, calling other skills as needed
Workflow skillsWalk you through a multi-step process — discovering data sources, setting up a project
Document skillsGenerate one specific deliverable from a template — data contract, runbook, architecture diagram, requirements doc
Capability skillsDo one specific thing — connect to Databricks, profile a table, query a catalog

Ask the concierge what's available and describe your task in plain language.

Q: What's a good first task if I'm brand new?

Point it at a small set of approved files with a clear output. A good starter prompt:

Review the files in this workspace. Summarize the main themes, key facts,
decisions, risks, and open questions. Identify the source file for each key
point, do not make assumptions when information is missing, and recommend one
useful output that could be created from these files.

Then check the result against the original files before attempting anything more complex.

Q: Catalyst told me something about the DPLC I don't understand. Where do I go?

Catalyst is an accelerator, not a replacement for fundamentals. The layers:

QuestionGo to
Governance, ownership, process, "what phase am I in?" The Paved Path on DevHub — the guided, standardized way to reach platforms and supported capabilities, and the curated toolkit Data Product Creators are expected to build with. It is the practical face of the Data Excellence Platform (DxP). Useful framing from that page: the lifecycle is the journey (phases, gates, checkpoints) and the Paved Path is the road — which tools to use at each phase, which standards apply, and where to get help. It also covers requesting a training environment, what is provisioned, feature availability, and the roadmap.
Technical standards, implementation patterns, production readiness, troubleshooting Causeway — the implementation layerlink pending
"Why does this part of the ecosystem exist?" Federated Data Ecosystem — the architectural glossary and ARB proposal
What the lifecycle phases and gates actually are Data Product Lifecycle — All Phases, Plain-Language Guide is the readable one: all eight phases (0 Pre-requisite through 7 Evolve), what good looks like, the gate question for each, and which artifacts are Required, Recommended or Optional — written for technical and non-technical readers alike. Start there if you are asking "what phase am I in, and what do I owe?".
RFD 0002 is the version Catalyst implements, and is what the skills enforce. The plain-language guide describes RFD 0009, which is not held in this repo — if the two ever disagree on a gate, raise it rather than guessing. Note the lifecycle is not strictly linear: a failed gate routes back to the phase that can fix it — a feature request to Phase 1, a breaking change to Phase 2 — rather than back to the start.
"What is Catalyst not?" It is not a data platform, a governance authority, or a replacement for the fundamentals. Catalyst is a plugin that runs on top of a coding agent and encodes the DPLC and the Paved Path as skills — it can draft the artifact a gate expects and tell you what the gate expects, but it does not grant the gate. Approvals, ownership, and sign-off stay with the Data Owner and the governance process. It also does not replace M365 Copilot for everyday drafting, and it will not turn an unclear business need into a good data product. AI Catalyst: Living FAQ goes deeper.
