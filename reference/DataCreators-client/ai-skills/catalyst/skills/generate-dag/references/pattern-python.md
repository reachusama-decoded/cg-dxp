# Pattern C — pure-Python TaskFlow

Authoring directly in Python with `@dag` / `@task`. Used when:

- The schedule needs features YAML loaders can't express cleanly —
  multi-Asset triggers (`schedule=[Asset(...), Asset(...)]`), dynamic
  task mapping, conditional branching with custom Python.
- The team explicitly opts out of YAML-driven authoring.

This is **opt-in only**. Default is `dag-factory` (or `astro-blueprints`
if the team's repo is wired for it).

## When chosen

- User passes `pattern=python` to the skill.
- Skill auto-falls-back to python when:
  - `schedule` resolves to multiple Assets and the team uses `dag-factory`
    (`dagfactory` doesn't expose Asset lists cleanly through YAML).
  - The compute step needs dynamic task mapping that YAML can't express.

When the skill auto-falls back, it prints the reason and the alternative
("could also be done in astro-blueprints if your repo has the framework")
so the user has a chance to redirect.

## Output path

```
data_products/<product>/datasets/<dataset>/airflow/<dataset>_dag.py
```

The team's Airflow `dag_folder` must include `data_products/` for direct
Python DAG scanning. Verify in `airflow.cfg` (or the Astronomer
equivalent) before emitting.

The callbacks imported below (`include.callbacks.*`) live at repo-root
`include/callbacks/*.py`. Astronomer's Astro Runtime auto-adds `include/`
to `sys.path`, which is what makes `from include.callbacks.X import callback`
resolve at DAG-parse time.

## Template (production mode, Asset-driven trigger)

```python
"""<dataset> — generated by /generate-dag on <DATE>.

RFD 0011 compliance summary:
- §1 Idempotency (PY-AIRFLOW-001): partition writes keyed on {{ '{{ ds }}' }}.
- §2 Retries (PY-AIRFLOW-003/004/016): 3 retries, exponential backoff capped at 30m,
     deterministic failures fail fast via AirflowFailException.
- §3 Deferrability (PY-AIRFLOW-017): deferrable operators; bounded execution_timeout.
- §4 Parallelism (PY-AIRFLOW-018): max_active_runs=1, max_active_tasks=4.
- §5 Schedule (PY-AIRFLOW-019): Asset-driven on <upstream>_ready.
- §6 Tags + routing (PY-AIRFLOW-007/008): Datadog alerting is platform-side
     (Astronomer); criticality + xMatters group are context support reads to
     escalate manually to Teams/xMatters. No DAG-level callback.
- §7 TaskFlow + thin DAG (PY-AIRFLOW-009/010): no module-scope I/O.
- §8 DAG ID convention (PY-AIRFLOW-012).
- §9 Secrets via conn_id (PY-AIRFLOW-013/020).

Local dev (PY-AIRFLOW-021):
    astro dev start
  airflow tasks test <app>__<dataset>__<frequency> run_<dataset>_dbt <YYYY-MM-DD>
"""

from __future__ import annotations

from datetime import datetime, timedelta, timezone

from airflow.decorators import dag, task
from airflow.providers.databricks.operators.databricks import DatabricksRunNowOperator
from airflow.sdk import Asset

from include.callbacks.on_success_log_databricks_url import callback as on_success_log_databricks_url

UPSTREAM = Asset("<upstream-dataset>_ready")
OUTPUT = Asset("<l1-domain>.<dataset>")


@dag(
    dag_id="<app>__<dataset>__<frequency>",                # PY-AIRFLOW-012
    schedule=[UPSTREAM],                                    # PY-AIRFLOW-019
    start_date=datetime(<YYYY>, <MM>, <DD>, tzinfo=timezone.utc),  # PY-AIRFLOW-002
    catchup=False,                                          # PY-AIRFLOW-006
    max_active_runs=1,                                      # PY-AIRFLOW-018
    max_active_tasks=4,                                     # PY-AIRFLOW-018
    render_template_as_native_obj=True,
    tags=[                                                  # PY-AIRFLOW-007
        "l1_domain:<l1-domain>",
        "l1_xmatters_group:<l1-xmatters-group>",
        "lifecycle_phase:<lifecycle-phase>",
        "data_classification:<classification>",
        "criticality:<criticality>",
    ],
    default_args={
        "owner": "<owner-email>",
        "retries": 3,                                       # PY-AIRFLOW-003
        "retry_delay": timedelta(minutes=5),                # PY-AIRFLOW-004
        "retry_exponential_backoff": True,
        "max_retry_delay": timedelta(minutes=30),
        # PY-AIRFLOW-016 — deterministic failures fail fast by raising
        # AirflowFailException from task code. Airflow has no per-operator
        # retry predicate; the scheduler hard-codes the rule.
        "execution_timeout": timedelta(hours=1),            # PY-AIRFLOW-017
        # PY-AIRFLOW-008 — no DAG-level failure callback: Datadog alerting is
        # provided by Astronomer at the platform level, not emitted by the DAG.
        "on_success_callback": on_success_log_databricks_url,
        "pool": "databricks_<tier>",                        # PY-AIRFLOW-005
        "pool_slots": <n>,
    },
    doc_md=__doc__,
)
def <app>__<dataset>__<frequency>():
    run_dbt = DatabricksRunNowOperator(
        task_id="run_<dataset>_dbt",
        job_name="{{ var.value.databricks_job_prefix }}<dataset>_job",
        databricks_conn_id="caspian-ig-databricks",         # PY-AIRFLOW-013
        deferrable=True,                                    # PY-AIRFLOW-017
        outlets=[OUTPUT],                                   # PY-AIRFLOW-015 — Asset on success
    )

    return run_dbt


<app>__<dataset>__<frequency>()
```

## Notes

- `Asset` outlets on `DatabricksRunNowOperator` give downstream DAGs a
  trigger without an explicit `kafka_notify` / `emit_data_ready` call. Add
  one only when an external consumer expects an event payload distinct
  from the Asset signal.
- Module scope is minimal: imports, two `Asset` constants, the `@dag`
  definition. No `Variable.get` at parse time (PY-AIRFLOW-009 +
  PY-AIRFLOW-013). Callbacks resolve secrets inside their own bodies, not
  at import.
- No DAG-level `on_failure_callback`: failure alerting (PY-AIRFLOW-008) is
  provided by Astronomer's platform Datadog integration. Teams notification and
  xMatters paging stay manual — see `references/mds-tags.md` for the routing
  model.
