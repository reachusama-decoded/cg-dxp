v1.7.0 — DAG Validation, DAB Rebuild, and Phase 6 Fixes

June 15, 2026

Three improvements in v1.7.0:

  • /validate-dag — new read-only RFD 0011 compliance auditor for existing DAGs
  • /setup-databricks-asset-bundle — rebuilt to match the DAB structure used by Capital Group data products today
  • /dplc-publish — Phase 6 no longer forces artifacts the data product doesn’t need (RFD 0002)

1. /validate-dag — RFD 0011 DAG Compliance Auditor

Read-only counterpart to /generate-dag. Point it at an existing DAG file and it applies the full RFD 0011 rule set (PY-AIRFLOW-001..022 + DBX-DAB-001/-003) and produces a Markdown compliance report with a grep-able VERDICT: line. Covers dag-factory, astro-blueprints, and pure-Python TaskFlow patterns across all four modes.

If you’re running DAGs in production, this is the quickest way to see where you stand against RFD 0011 before making changes.

2. /setup-databricks-asset-bundle — Rebuilt for Capital Group Data Products

Rebuilt to match the DAB structure used by Capital Group data products today. references/ + templates/ layout, variables/ directory with per-env overrides and clusters.yml, two jobs per dataset (dbt + Deequ DQ), 8 targets including DR variants.

If you ran the v1.5.0 skill and got a bundle that didn’t pass databricks bundle validate — this is the fix.

3. /dplc-publish — RFD 0002 Conditional Necessity

Previously required all three Phase 6 leaf artifacts. Now honors RFD 0002: consumer onboarding guide and release notes are Optional — conditional on external consumers or a versioned multi-team product. The Phase 6 gate passes without forcing artifacts the data product doesn’t need.

Internal, single-team products can now clear Phase 6 without writing an onboarding guide or release notes they’d never use.
