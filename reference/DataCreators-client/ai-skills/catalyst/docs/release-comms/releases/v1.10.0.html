v1.10.0 — Local Airflow Orchestration + Pipeline Standards

July 13, 2026

This release extends the Phase 4 build inner loop from Databricks bundles to Airflow. The new /deploy-airflow-local skill stands up your DAG locally so you can iterate on orchestration without leaving Copilot Chat — and two ratified standards give data-pipeline builders clearer guidance on testing and containerization.

What’s new in v1.10.0:

  • /deploy-airflow-local — new skill that runs your data product’s DAG locally, closing the Phase 4 loop for Airflow orchestration
  • Testing strategy, ratified — a tiered testing standard for data pipelines, mapping each layer of coverage to the skill that produces it
  • Containerization guidance — a new language guide for building containers the right way on the corporate network

1. /deploy-airflow-local — Run Your DAG Locally

The Airflow counterpart to /deploy-dab. Once your data product has a DAG, /deploy-airflow-local spins up a local Airflow runtime and triggers it in your own environment — so you can validate orchestration end-to-end before anything ships to a shared environment.

This is your personal dev iteration loop for orchestration. Shared and remote Airflow deploys remain a separate, in-progress capability.

2. Testing & Containerization Standards

Two standards are now ratified. The testing strategy lays out a tiered model — unit, integration, and data-quality — and points you to the Catalyst skill that produces each layer, so you know what to test and where. The containerization guide adds concrete rules for building images, including sourcing base images and packages from the internal mirrors rather than public registries.

If you build or review data pipelines, these give you a single reference to point to instead of tribal knowledge.

What’s next

  • Remote Airflow deploy — extending the local orchestration loop to shared Astronomer environments
  • Operate & Evolve phases — promoting today’s leaf skills (runbooks, incident logs, deprecation notices, usage analytics) into full phase orchestrators

A note on platforms

Catalyst is validated primarily on macOS. Windows users can use it, but may hit gaps in the technical prerequisites for some skills — local tooling setup, available compute, and environment configuration. If you’re on Windows and something doesn’t work, please tell us via catalyst-feedback.
