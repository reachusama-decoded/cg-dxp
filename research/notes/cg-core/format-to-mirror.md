# What "similar to ts-cg-core" means in practice

`reference/ts-cg-core` is the CG Core programme workspace (nine half-day sessions; Sessions 01 and 02 built). Its conventions live in `.claude/skills/` (programme-profile, lesson-plan, lesson-build, module-demo, module-challenge, courseware-conventions). The shapes worth copying for the Data Creators delivery pack:

| Artefact | CG Core shape | What to borrow for Data Creators |
|---|---|---|
| Lesson plan (instructor) | `instructor/module00-overview/dayNN_lesson_plan.md`: overview, objectives table (verb, evidence), curriculum map, before the session (materials table, checklist before/on/after the day, learner setup check), then a timeline of rows `H:MM · N min · type — title` each with Purpose, On screen, Instructor notes, Say, Transition, Assessment; then per-module reference, question bank, support and stretch, FAQs. Built to Word. | The per-day **run sheet**: the instructor plan's timetable rows expanded with purpose, on screen, whiteboard script (questions and expected answers), say, transition, and a "if ahead / if behind" note. |
| Overview (learner) | `learner/module00-overview/dayNN_overview.md`: persona card, the questions, outcomes, before you start, setup, agenda. | Not needed: learners have the book and the repo READMEs. A one-page **day agenda** for the screen is enough. |
| Demo notebook (instructor) | `instructor/moduleNN-<slug>/dayNN_mN_demo.ipynb`: module map, visual-first beats, code cells only where something runs, ends with a Challenge-time box and one Go-deeper box. Files it opens sit beside it. | **Demo scripts** per block: exact prompts, files to open, commands to run, what the room should see, fallback if the tool is slow or blocked. Jupyter notebooks for the dbt and Airflow demos (runnable inside the training dev container), Markdown for the Catalyst/Copilot/Docker/Databricks UI walkthroughs. |
| Challenge notebook (learner) | `learner/moduleNN-<slug>/dayNN_mN_challenge.ipynb`: difficulty legend, Q1/Q2/Q3 task boxes, reflect box, folded solutions, your-turn boxes. | **Activity cards** for the group challenges (brief, grouping, time, outputs, debrief questions) as Markdown pages that render well on a projector and print to one page. The technical practicals stay in the client repo's READMEs. |
| Challenge solution (instructor) | `instructor/moduleNN-<slug>/challenge-solution/` with outputs. | **Worked artefacts**: a reference PRD, data contract, STTM and SLA set for one running example product; a generated dbt project and DAG from that contract; the HTML contract render. Used when Catalyst is slow or blocked and in debriefs. |
| Figures | `courseware/common/figures/dayNN/` (Mermaid/SVG). | The **whiteboard diagrams** as Mermaid/SVG so they can go on a slide if the whiteboard is bad: three views of a data product, triage questions, costs/benefits/adoption, STTM, SLI/SLO/SLA and nines, paved path, data systems timeline, Docker image/container, dbt layers, DAG and callbacks, bitemporal timeline, GitOps/Harness. |
| Slides | `dayNN_slides.md` → pptx via `scripts/make_slides.py`; Decoded template. | Optional: a short deck per day (title, agenda, the diagrams, the activity briefs). The Cohort 3–5 deck (149 slides) exists but does not follow the Cohort 7 / instructor-plan flow. |
| Programme files | `unit00-programme/instructor/start-here.md`, `delivery-guide.md`, `event-readiness.md`, `release-notes.md`. | **Instructor start-here** for the week (people, logistics, pre-flight checklist, risks, what to send learners before Monday). |

House rules that still apply when writing for CG (from courseware-conventions and the profile): Decoded voice, pros-and-cons never "limitations" of a tool, nothing identifiable or secret, Catalyst first for "at CG" questions, keep it simple, define terms at first use, they/them for invented people.
