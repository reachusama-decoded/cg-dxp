# Pattern A — dag-factory

The default emission pattern. Uses the open-source `dag-factory` library to
generate Airflow DAGs from declarative YAML. More portable than
astro-blueprints; less abstracted.

## When chosen

- Default for new teams without an existing blueprint framework.
- Repo has no `.blueprints/*.py` files.
- User explicitly requests dag-factory.

## Output path

```
data_products/<product>/datasets/<dataset>/airflow/<dataset>.dag-factory.yml
```

Cite `skills/scaffold-repo-structure/references/repo-structure.md` for the
canonical layout.

## Template (production mode, Asset-driven trigger)

```yaml
# data_products/<product>/datasets/<dataset>/airflow/<dataset>.dag-factory.yml
# Generated by /generate-dag (Catalyst) — <DATE>
# Do not hand-edit; re-run /generate-dag to regenerate.
# RFD 0011 §1 — partition-keyed write; MERGE on identity key; no watermark table
# RFD 0011 §4 — Asset-driven trigger; catchup False

dag_id: "<app>__<dataset>__<frequency>"         # PY-AIRFLOW-012 — 3-part convention
schedule:
  - dataset: "<upstream-dataset>_ready"          # PY-AIRFLOW-019 — Asset-driven default; RFD 0007 trigger
catchup: false                                   # PY-AIRFLOW-006
render_template_as_native_obj: true
start_date: "<TODAY-UTC>"                        # PY-AIRFLOW-002

max_active_runs: 1                               # PY-AIRFLOW-018 — bound DAG-level parallelism
max_active_tasks: 4                              # PY-AIRFLOW-018

default_args:
  owner: "<owner-email>"
  retries: 3                                     # PY-AIRFLOW-003
  retry_delay_seconds: 300                       # PY-AIRFLOW-004
  retry_exponential_backoff: true
  max_retry_delay_seconds: 1800                  # PY-AIRFLOW-004 — cap exponential backoff at 30m
  # PY-AIRFLOW-016 — retry_on_exception is NOT a real Airflow API: BaseOperator
  # has no such parameter. Airflow's retry decision is hardcoded — the scheduler
  # skips retry only for AirflowFailException (and AirflowSensorTimeout for
  # sensors). Deterministic failures must therefore raise AirflowFailException
  # from the task callable; transient signals propagate normally and retry per
  # the retries/retry_delay settings above. Same rule applies to all patterns.
  # PY-AIRFLOW-008 — no DAG-level failure callback: Datadog alerting is provided
  # by Astronomer at the platform level, not emitted by the DAG.
  on_success_callback: "include.callbacks.on_success_log_databricks_url.callback"
  execution_timeout: 3600                        # PY-AIRFLOW-017 — bounded waits; no unbounded operators
  # sla:                                          # only emit if data contract has SLA field
  #   minutes: <from-contract>                    # NEVER default; see compose-with-bundle.md

tags:                                            # RFD 0011 §6 PY-AIRFLOW-007 — required tag set
  - "l1_domain:<l1-domain>"
  - "l1_xmatters_group:<l1-xmatters-group>"
  - "lifecycle_phase:<lifecycle-phase>"           # build | operate | decom
  - "data_classification:<classification>"
  - "criticality:<criticality>"                   # critical | high | standard
  # Optional (uncomment as needed):
  # - "l2_xmatters_group:<l2-xmatters-group>"
  # - "l3_xmatters_group:<l3-xmatters-group>"
  # - "app_id:<app-id>"

tasks:
  run_databricks_job:
    operator: airflow.providers.databricks.operators.databricks.DatabricksRunNowOperator
    # RFD 0011 §6 — DatabricksRunNowOperator for all compute; no PythonOperator for calculations
    databricks_conn_id: "{{ conn.databricks_default.conn_id }}"  # RFD 0011 §8 — Astronomer Connection
    job_name: "{{ var.value.databricks_job_prefix }}<dataset>_job"  # RFD 0011 §8
    notebook_params:
      execution_date: "{{ ds }}"
      partition_key: "{{ ds }}"                  # RFD 0011 §1 — partition-keyed idempotency
    pool: "databricks_<tier>"                    # PY-AIRFLOW-005 — T-shirt tier
    pool_slots: <n>                              # PY-AIRFLOW-005
    deferrable: true                             # PY-AIRFLOW-017 — release worker slot while waiting

doc_md: |
  ## <dataset>

  **Owner:** <owner-email>
  **xMatters group:** <l1-xmatters-group> (criticality: <criticality>)

  ### Local dev (PY-AIRFLOW-021)

  ```
  astro dev start
  airflow tasks test <app>__<dataset>__<frequency> run_databricks_job <YYYY-MM-DD>
  ```

  Validate locally before pushing; CI is the safety net, not the inner loop.

  ### Rerun

  Pause the DAG, clear the affected logical date, then unpause. Writes are
  partition-keyed (PY-AIRFLOW-001) so reruns are safe.
```

## Placeholder fill-in

Skill replaces each `<placeholder>` with discovery-step output:

| Placeholder | Source |
|---|---|
| `<app>` | User input (Step 3 MDS app_id, or derived from product name) |
| `<dataset>` | Skill arg |
| `<frequency>` | Step 4 trigger mode output (`daily`/`hourly`/`weekly`/etc., snake_case token) |
| `<upstream-dataset>` | Step 4 trigger mode (only if Asset-driven) |
| `<TODAY-UTC>` | Generation time, UTC |
| `<owner-email>` | Step 3 MDS owner (lives in `default_args.owner`, not in `tags`) |
| `<l1-domain>` | Step 3 — data contract `domain` field or user input |
| `<l1-xmatters-group>` | Step 3 — AD group name; context support reads (alongside Datadog's tag-based monitors) for manual xMatters escalation — not carried by a DAG-emitted event |
| `<lifecycle-phase>` | Step 3 — `build` for new DAGs |
| `<classification>` | Step 3 — data contract `classification` (never default) |
| `<criticality>` | Step 3 — `critical` / `high` / `standard` (no default; resolve via Step 3 prompt mapping) |
| `<tier>` | Step 5 resourcing tier (xs/sm/md/lg) |
| `<n>` | Pool slot count per tier (1/2/4/8) |
| `databricks_job_prefix` resolution | `variables_<env>.yml#databricks_job_prefix` per env |

## SLA handling

If the data contract has an SLA field, emit `sla:` with the contract value.
If absent, emit the commented-out `# sla:` block with a comment directing
to the data contract owner. NEVER default a value (per spec §5).

## Cron-fallback variant (no Asset trigger)

When trigger mode is schedule rather than Asset-driven:

```yaml
schedule: "0 3 * * *"                            # RFD 0011 §4 — cron fallback
# RFD 0011 §4 — schedule-cron chosen. Consider migrating to Asset-driven
# trigger once the upstream DAG is identified.
```

Replace the `schedule:` block in the template above with the cron string +
advisory comment.

      min: 0
      max: 10000000
  - name: no_null_in_primary_key

    args:
      column: "<primary-key-from-contract>"
  # Additional checks derived from data contract DQ rules
