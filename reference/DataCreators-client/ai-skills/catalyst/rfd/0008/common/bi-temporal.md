# Bi‑Temporal Table Design
**Foundation Reference – Examples & Best Practices**

This document provides a practical reference for implementing **bi‑temporal data modeling**, aligned with Capital Group’s ADR guidance and enterprise data standards.

---

## Overview

Bi‑temporal modeling tracks data across **two independent timelines**:

1. **Business Date (Valid Duration)**  
   When a fact is true in the real business world.

2. **System Time (Transaction Time)**  
   When the system stored or believed the fact to be true in the data lake.

This design enables:
- Full historical reconstruction
- Retroactive corrections without data loss
- Point‑in‑time (“as of”) reporting
- Compliance‑grade audit trails
- Advanced SCD Type‑2 behavior with correction history

---

## Core Concepts

### Business Date (Valid Duration)
Represents the real‑world validity of a fact.

Examples:
- Customer address effective date
- Policy coverage start and end date

Typical columns:
- `business_start_date`
- `business_end_date`

---

### System Time (Transaction Time)
Represents when the data lake recorded or corrected the information.

Key characteristics:
- Immutable history
- Corrections create new rows
- Previous versions are closed, not overwritten

Typical columns:
- `system_start_timestamp`
- `system_end_timestamp`

---

### Audit Columns
- `dl_row_uid`: Surrogate key generated by `generate_surrogate_key_v3()`
- `dl_checksum_value`: SHA1 hash for change detection
- `dl_last_update_process_id`: Audit trail for data lineage

---

## Typical Bi‑Temporal Table Structure

| Component | Description |
|---------|-------------|
| Business Key | `listing_uid`, `portfolio_uid` |
| Business Attributes | `name`, `type`, `status` |
| Valid Time Columns | `business_start_date`, `business_end_date` |
| System Time Columns | `system_start_timestamp`, `system_end_timestamp` |
| Audit Columns | `dl_row_uid`, `dl_checksum_value` |
| Constraints | Prevent overlapping valid‑time intervals per business key |

---

## Example Table Definition (Generic SQL)

```sql
CREATE TABLE listing (
    listing_uid     INT NOT NULL,
    listing_name         VARCHAR(255),

    -- Business Time
    dl_business_start_date      DATE NOT NULL,
    dl_business_end_date        DATE NOT NULL,

    -- System Time
    dl_system_start_timestamp        TIMESTAMP NOT NULL,
    dl_system_end_timestamp          TIMESTAMP NOT NULL
);
```
---

## Query Patterns

### Active Records Only
```sql
SELECT * 
FROM cspn_fndn2.issuer
WHERE dl_current_indicator = 'Y'
```

### Historical Records
```sql
SELECT * 
FROM cspn_fndn2.issuer
WHERE '2024-01-15' BETWEEN dl_business_start_date AND dl_business_end_date
```

### As-of-Date Query (Balance Load)
```sql
SELECT * 
FROM cspn_fndn2.investment_portfolio_transaction
WHERE dl_current_indicator = 'Y'
  AND activity_date = '2024-01-07'
```


### Point-in-Time Query (System Time)
```sql
SELECT * 
FROM cspn_fndn2.issuer
WHERE '2024-01-15 18:00:00' BETWEEN dl_system_start_timestamp AND dl_system_end_timestamp
```
