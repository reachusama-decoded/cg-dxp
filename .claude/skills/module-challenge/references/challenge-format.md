# Challenge format

One challenge notebook per module (user, 2026-10-27), `learner/moduleNN-<slug>/dayNN_mN_challenge.ipynb` (or `.md`), and Put it together's own, `learner/module99-put-it-together/dayNN_together_challenge.ipynb`, each standing alone with the short, identical nbkit header (title, table of contents, two lines of how to use, the Copilot legend, one setup cell and the challenge data card), in AIA's box set built with `nbkit` (`scripts/nbkit.py`; the exact HTML is in `lesson-build/references/notebook-boxes.md`). Starter files sit beside it only where a task needs them. The way of working is the programme's (`programme-profile/references/conventions.md` → "Learners direct AI and review what it wrote"): learners prompt Copilot to write, fix or change the code and review what it wrote; they never type code or do the maths by hand.

## The folder

```
learner/moduleNN-<slug>/   # e.g. learner/module04-unit-testing-pytest/ (no challenge/ subfolder; the handbook sits here too)
  dayNN_mN_challenge.ipynb      # the module's challenge notebook (day02_m4_challenge.ipynb), shipped without outputs
  m1_fund_report_copilot.py     # one starter file the module adds: module prefix (here, a first draft to review, with planted faults)
  m4_fund_report/               # the module's project folder, beside the notebook that uses it
learner/module99-put-it-together/
  dayNN_together_challenge.ipynb + together_fund_report/   # Put it together, its own module folder, with its catch-up folder
instructor/moduleNN-<slug>/challenge-solution/  # the learner module folder's challenge files, same names, one level deeper; every task done (instructors only)
  dayNN_mN_challenge.ipynb      #   executed, with outputs; answer boxes filled
  m1_fund_report_copilot.py     #   the fixed version, under the same name
  report.txt …                  #   plus any file the tasks make
```

The module's challenge files are self-contained: nothing in them imports, opens or names a demo file, the demo anchor or a path into `instructor/` (shared containers live in `courseware/common/services/`; starting one is setup, so the challenge may use it, at `../../../../common/services/<name>/` from the notebook).

## Notebook furniture (the short nbkit header)

- **Cell 1**: the Decoded title cell, `nbkit.title_cell("<session title>", nbkit.breadcrumb(<unit>, "<unit title>", NN, "challenge notebook"))` (no version line).
- **Cell 2**: the 🗺️ table of contents, its own cell (id `toc`), generated by `scripts/nbkit.py toc --nb learner/moduleNN-<slug>/dayNN_mN_challenge.ipynb` after `write()` and never typed: a row per `## ` section from How to use on, each linking to the anchor line nbkit puts at the top of that heading cell, and listing the section's task boxes ("Q1 Core: <title>"), your-turn boxes and `### ` headings other than the answer boxes. It names no minutes and never the handbook (`lesson-build/references/notebook-boxes.md` → "Table of contents").
- **Cell 3**: the short, identical how to use (two lines, generated by nbkit): this module's task; the data is the challenge data at `../../../../common/data/challenge`; everyone starts at Q1 and goes as far as they can, no tier is mandatory and Q3 is not expected; Put it together is the optional stretch for fast finishers; you ask Copilot to make every code change, review what it wrote and run the check; reflect before you open a solution. Then the difficulty legend, `nbkit.difficulty_legend_html()`, and the Copilot settings legend, `md(nbkit.copilot_legend())` (in this cell or the next), which explains each badge the 🤖 COPILOT boxes and folded solutions use.
- **Cell 4**: the setup cell: imports, the data path from the anchor (`DATA = Path("../../../../common/data/challenge")`), a file check that says what to do if something is missing. Nothing from the demo.
- **Last cell**: the footer.

## One module's section

In cell order (a builder script in the scratchpad, `sys.path.insert(0, "<repo>/scripts")` then `from nbkit import *`):

```python
md("## Module 1 challenge — Fix and review the report script")
# the 🧭 anchor cell goes here: written afterwards by `scripts/nbkit.py anchors --session <folder>`
# from dayNN_anchors.md, never typed in the builder
md(
    "This builds on <the files, numbers and repository it starts from, named concretely>. "
    "The map below recaps the demo this challenge follows."
)
md('<img src="../../../../common/figures/day01/m1-map.png" width="900"/>')
md(
    task_box(
        1,
        "Fix the report cell",
        "Individual",
        "<one-line goal>",
        [
            "Run the cell below and note the three things a traceback tells you.",
            "Ask Copilot <code>/explain</code>; check its explanation against the traceback.",
            "Select your line, press Ctrl+I (Cmd+I on a Mac) and ask Copilot to fix the cause; read the diff in the cell and choose Accept and Run, which reruns it: <the check>.",
        ],
    )
)
# a prompt the task hands learners
md(
    copilot_prompt(
        "Explain the error",
        "/explain Why does this cell stop with this KeyError?",
        mode="Ask",
        model="Fast",
        attach="selection",
    )
)
# one change to one line: Inline chat, no mode, no ATTACH selection
md(
    copilot_prompt(
        "Fix the cause",
        "Fix the cause of the error in the selected line:\n<what is wrong, and what it should be>.\nChange nothing else.",
        None,
        "Fast",
        purpose="Select your own line in the cell first, then press Ctrl+I (Cmd+I on a Mac).",
        where="Inline chat",
        then=COPILOT_THEN_NOTEBOOK_CELL,
    )
)
# in a notebook cell VS Code offers Accept and Run (applies the change and reruns the cell), not the editor's Keep and
# Undo, so the box passes nbkit's notebook-cell line, or one fitted to the task that names Accept and Run and no reject
# button; a box for a .py file in the editor keeps the default Keep or Undo line
# Inline chat sees only the selected lines, so its prompt carries what they can't show (a column's real name, say),
# and the task says where learners find it (the data README) and gives My reading a line for it
code("<the complete starting code, with its planted fault>")
# gaps only record
md(
    "**What I read:** the error type `___`, the line `___`. **Accept and Run, or ask again, and why:** ___"
)
md(
    reflect_solution(
        "<a why-question>",
        copilot_solution(
            "<a prompt a learner could type>",
            "<the fixed code>",
            "<the check and its number>",
            model="Fast",
            where="Inline chat",
        ),
        "<two or three sentences>",
    )
)
md(
    task_box(
        2,
        "<title>",
        "Individual",
        "<goal>",
        [
            "Open <code>m1_…_copilot.py</code> …",
            "Ask Copilot to …; review every changed line …",
            "Run the check …",
        ],
    )
)
md(
    terminal_box(
        "<what to run>",
        "Open a terminal in the <code>challenge</code> folder.",
        "python m1_…_copilot.py",
    )
)
md(
    writing_cell(
        "My checks", "Prompt, mode, model, one review note, the check and its result."
    )
)
md(
    reflect_solution(
        "<why>",
        copilot_solution(
            "<prompt>",
            "<fixed code>",
            "<check>",
            mode="Agent",
            model="Fast",
            attach="#m1_…_copilot.py",
        ),
        "<answer>",
    )
)
md(your_turn_box("<title>", "<strong>The question.</strong> Where the answer goes."))
md(
    task_box(
        3,
        "<title>",
        "Individual",
        "<goal>",
        ["Write a five-part brief; run it in Agent mode …", "Review it line by line …"],
    )
)
md(
    reflect_solution(
        "<why>",
        copilot_solution(
            "<model brief>",
            "<fixed code>",
            "<check>",
            mode="Agent",
            model="Reasoning",
            attach="#m1_…_copilot.py",
        ),
        "<answer>",
    )
)
md(go_deeper(1, "<what the handbook adds>"))
```

- **The 🧭 anchor and the bridge** open every section, the put-it-together task included: the heading cell, the anchor cell (generated, identical to the demo's), then the bridge cell ("This builds on …", concrete). Then **the recap visual**, before the first task: one visual of the demo section it follows, reused from `courseware/common/figures/dayNN/` (the module map or the key concept card) or the demo's Mermaid flow. It reminds the learner what they saw; it does not teach anything new, and it carries no "The proper words" line.
- **Task boxes**, one per tier, Q1 first: Q1 · CORE for everyone, Q2 · STRETCH, Q3 · BONUS not expected (the helper adds the line if the text does not say so). Header: title and Individual or Pairs, no minutes (no times anywhere in a challenge notebook; the demo's 🏆 CHALLENGE TIME box gives the challenge time). Body: a bold one-line goal, then short "Task N.k —" lines numbered by tier, each an instruction to Copilot, a review or a check. Q1 fits the challenge time for most of the room; nobody has to reach Q2 or Q3.
- **Starting code, not gaps.** A code cell after a task box holds complete code with its planted fault (a column the challenge data does not have, a filter that drops rows, an `except` that hides errors, a path tied to the terminal's folder): the learner finds it by reading and running, and Copilot fixes it at their direction. Code cells never carry `___` or `# TODO` for the learner to write; a `___` in markdown or a string records what they observed or decided.
- **🤖 COPILOT** around every prompt the task hands learners, straight after its task box (`copilot_prompt(title, prompt, mode, model, attach=None, purpose=None, then=None, where="Chat view")`): WHERE Chat view, Inline chat or Terminal chat (pass `mode=None` with the last two: Terminal chat for a shell command, Inline chat for one change to the selected code, with a purpose line that says which lines to select and no ATTACH `selection`; in a notebook cell it passes `then=COPILOT_THEN_NOTEBOOK_CELL` or its own line naming **Accept and Run**, the button VS Code shows there, while a `.py` file in the editor keeps Keep or Undo), MODE Ask, Plan or Agent (Chat view only), MODEL Fast, Reasoning or Auto, ATTACH `#<file>`, `selection`, `#codebase`, `#terminalLastCommand` or `#terminalSelection` when the prompt needs context, prompt lines under about 90 characters (`programme-profile/references/conventions.md` → "The Copilot box"). Where learners write their own prompt (a brief), the task box asks for it and the model prompt is only in the folded solution. A prompt is never a blockquote or a bare fenced block.
- **⌨️ TERMINAL** before every terminal step, with the commands in the same cell (`terminal_box(title, body, commands)`).
- **💭 REFLECT, then the folded solution**, in one cell: the question shows before the `<details>`; the solution shows a model prompt with its Copilot settings (`copilot_solution(prompt, change, check, mode=…, model=…, attach=…, where=…)`, where `mode` defaults to Ask in Chat view and to none in Inline chat or Terminal chat: "**A prompt that works:**", the WHERE, MODE (Chat view only), MODEL and ATTACH badges and the prompt in a ```` ```text ```` block, several prompts in one block with a blank line between them; never a blockquote), the change a good answer makes and the check that proves it, then "**Reflect — answer:**". The solution is never a code cell.
- **🎯 YOUR TURN** for a short task with no code (name a lifecycle stage, decide Keep or Undo): the answer goes in the cell below it.
- **A "My checks" cell** where the task produces a recorded check (S01 M1 Q2: prompt, mode, model, one review note, the check).
- **The Go deeper box** closes every module section, in its own markdown cell (`md(nbkit.go_deeper(N, body))`; a Markdown anchor pastes `nbkit.go_deeper_html(N, body)` as its own block). The spelling is fixed; only the body sentence changes: what the handbook adds (the full explanation, more worked examples, further reading), with no path, link, section title or number. It is the only place the challenge mentions the handbook (user, 2026-10-15).

Where a task uses a starter file: **Open** `m1_fund_report_copilot.py`, **run** it, **review** each function (ask Copilot to explain any line you would not have written), **come back** and record what you found.

A Markdown anchor (`dayNN_mN_challenge.md`) pastes each helper's `*_html` string as its own block (`copilot_prompt_html` and `copilot_legend_html` included), with fenced code for the starting code.

## The put-it-together task

The anchor's last section, `## Put it together — <task name>`, the optional stretch for fast finishers (user, 2026-10-16): learners who want it take it in the session's last block, open challenge time, while everyone else carries on with the module challenges. Its lead-in says it is optional and gives no time. The same boxes and way of working; its recap visual shows the artefact's journey through the session's modules (S01: written, run remotely, packaged). It needs all three modules' skills on the challenge data and ships the session's artefact. S01 (Ship your report): copy Module 3's package to the remote without `.venv` and `__pycache__` (`same-files`), build a fresh `.venv` there from `requirements.txt` (`same-set`), run the job in the background with a log and prove the laptop's table (`identical`). Stretch: a reviewed `run_report.sh` and a README Run on the remote section. Bonus: one `ssh` line runs the job. It starts from a state that a learner who stopped at Q1 or Q2 of each module reaches, never a Q3 result, and its first lines name that state (files, repository, branch). It has no Go deeper box. The closing debrief and the wrap-up are run from the lesson plan, not the anchor.

## Starter files

- Module prefix for one file, a named folder for several; never a placeholder for a module not yet built.
- Complete, runnable code. Where the task is to review a draft script, the file is named `*_copilot.py` and presented as a first draft to review, never as Copilot's mistakes (CG rule 2), and its faults are planted in what it does: nothing in the file (no comment, no marker, no name) says where they are. `module-audit` recognises planted-fault files by name only (`PLANTED_FAULTS` in `audit.py`: `mN_break_it.py`, `*_copilot.py`), lists them as notes and skips its path and error-handling checks for them; every other check still applies.
- A file without planted faults resolves its data by relative path from `Path(__file__)` to `courseware/common/data/challenge/`, never copied into the folder, and lets errors fail loud.
- `requirements.txt` only if the task needs something the dev container lacks, or inside a project folder that teaches its own pinned environment; either way its pins match `courseware/.devcontainer/requirements.txt`.
- A deterministic check where possible (a check cell, `mN_check.py`, pytest on a function, `curl /health`, `dbt test`), used by learners, instructors and reviewers; the folded solution names its number.
- Formatted with `scripts/format_code.py`; comments that would split a line go above the code (the formatter moves them). Starter files never mention the handbook.

## The completed challenge

`instructor/moduleNN-<slug>/challenge-solution/` (user, 2026-10-16) is the challenge done in full, so an instructor can show a finished version in the debrief. It sits one level deeper than the learner module folder, with the same file names as its challenge files, so its paths into `common/` go up one more level (five), and it has every challenge file `learner/moduleNN-<slug>/` has (not the handbook), under the same names, plus the files the tasks have learners make (S01's put-it-together: the `report.txt` baseline, `requirements.txt` and `README.md`). Build it once the challenge is verified, and rebuild it in the same pass whenever the challenge changes:

1. Copy the module's challenge notebook and its project files from `learner/moduleNN-<slug>/` to `instructor/moduleNN-<slug>/challenge-solution/` (tracked files only, not the handbook, no checkpoints or caches), and add one `../` to every path into `common/`.
2. Do every task with the model answer its folded solution gives, Q3 · BONUS and the put-it-together task included: put the fixed code in each starting cell and the cell Copilot writes in (the check), and replace each starter file with its fixed version under the same name (S01: `m1_fund_report_copilot.py` with its three problems fixed). A cell that names `challenge/` by path (S01 Q2's run from the folder above) points at `challenge-solution/` instead, so it runs the fixed file.
3. Fill every answer box with what the model answer saw and decided: My reading, My review, My checks (and My checks: shipping), the 🎯 YOUR TURN tables. No `___` is left; a `___` inside inline code in "How to use this notebook" is prose and stays.
4. Leave everything else as the challenge has it, with the same cell ids: title, the 🗺️ table of contents and every heading's anchor line, legends, task boxes word for word, 🤖 COPILOT boxes, the folded solutions, Go deeper boxes, footer. A cell only the completed challenge needs takes an id ending `-solution`. The audit compares every markdown cell but the answer boxes with the challenge's, by id. Once the answers are in, run `scripts/nbkit.py toc --nb instructor/moduleNN-<slug>/challenge-solution/dayNN_mN_challenge.ipynb`: a cell copied from an older completed copy may have lost its anchor line, and the table must match the challenge's.
5. Format (`.venv/bin/python scripts/format_code.py instructor/moduleNN-<slug>/challenge-solution/`), start the session's services, then execute it top to bottom from its own folder in the dev container image (Run All in the dev container, or `python -m nbconvert --to notebook --execute --inplace dayNN_mN_challenge.ipynb` in a throwaway container from its image) so it carries every output with sequential counts, no error output and no warning; outputs come from the dev container image, never from `.venv`. Check that no output shows an absolute home path or a key: where an output prints a resolved path (S01's wrong `REPORT_DATA` runs print the full path to `no-such-folder`), run it in the dev container on a copy of the course folder, or in a throwaway container from the dev container's image on such a copy, so the path reads `/workspaces/<course folder>/…`, never a home or `courseware` path. Do the terminal-box steps on the remote too, so the filled answer boxes quote what it really printed.
6. Run `module-audit` on the session folder. Don't clear it: unlike the challenge, it ships executed.

It never goes under `learner/`. After the user's review, `scripts/build-session.sh dayNN --reviewed` copies it to `release/latest/<unit>/<session>/instructor/challenge-solution/` so it runs as it is, and prints `instructor/dayNN_mN_challenge_solution.pdf` in the same session folder with `scripts/notebook_pdf.py --with-files` (the notebook with its outputs, the fixed files after it). Learner-facing text never mentions it; the lesson plan's debrief rows may point to the PDF (`lesson-plan` skill).

## Instructor material

What a finished challenge looks like (a line per tier, with the real numbers), the three likeliest stalls with a one-line hint each, and the five-minute debrief live in the module's block and reference section of `instructor/module00-overview/dayNN_lesson_plan.md`, never in the anchor. The planted faults are listed there for instructors, never in a learner file. The finished version to show in the debrief is `challenge-solution/` (above).

## Discussion or paired tasks

Same boxes; the task box header says Pairs. "You produce" is a written artefact (a decision table, a PR description, a review comment) that can be shown. A solo route is one line in the box ("working alone: write both sides"). Partners work in parallel on their own laptops and copies and swap only for the review; the task box says which step is the swap.
