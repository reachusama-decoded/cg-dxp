v1.12.0 — Data Quality Control Planning in Design

August 11, 2026

Three improvements in v1.12.0:

  • /data-quality-controls-plan — turn profiling findings into a short, enforceable set of data quality controls
  • Skills map — a browsable, interactive picture of all 103 skills and how they connect
  • /rfd-authoring — now loads correctly

1. /data-quality-controls-plan — Plan your data quality controls during Design

Takes what profiling found about your table, plus what the business actually needs, and proposes a focused set of data quality controls — not one rule per column. Each control is mapped to a named rule pattern from the Enterprise Data Governance Council’s standard, tagged with a quality dimension, and given a monitoring action (stop the pipeline, warn, or check at rest) with a written reason it exists. Each one also comes out as a DQ Next check, so the plan is directly implementable rather than a document that stops at good intentions.

The approved plan feeds straight into your data contract’s Data Quality Rules table, which stays the single source of truth once the contract is signed off. Run /data-quality-controls-plan in Phase 3, after profiling and before the contract is finalised.

Fewer rules, each one justified. A control with no action and no rationale doesn’t get added — the skill is built to resist rule sprawl and the alert fatigue that follows it.

Thank you to ARVS, LQXA and NKV for the data quality work behind this.

2. Skills map — See every skill and how they connect

Catalyst now publishes a browsable map of all 103 skills, grouped by lifecycle phase and wired together by the dependencies each skill declares. Filter by phase or skill type, search by name, hover a skill to light up its neighbours, or open one to walk its dependencies in both directions — what it needs, and what needs it. There is a plain table view as well.

Most useful when you are new to Catalyst and want to see the shape of the whole thing, or when you know roughly where you are in the lifecycle but not which skill comes next.

Thank you to CONNMS for contributing to this.

3. Updates & Enhancements

  • /rfd-authoring — the skill shipped previously but was never registered, so it could not load. It now works.
  • /data-contract — the quality rules table now receives an approved controls plan directly, using the columns it already had. Nothing about the contract’s structure changed.

4. Coming Soon

Two data quality governance questions came out of the recent working session and are now in open discussion. Neither is decided, and neither ships in this release — flagging them because they will shape how quality controls are owned and recorded:

  • Quality accountability artifact — whether the lifecycle should carry a named owner for each quality control, so it is clear who acts when one fires.
  • Quality dimension in the data contract — whether the contract’s quality rules table should carry the dimension as its own column, rather than inside the rule description.

If you have a view on either, the discussion is open and input is welcome.

Also shipped

  • Contribution guide — a step-by-step cookbook for adding, updating, or retiring a skill, now the front door for anyone who wants to contribute.
  • Release process — the end-to-end release cut is written down rather than remembered (Catalyst dev team).
  • Test harness — a structural check was renamed to match what it actually inspects, and it now fails clearly instead of passing on an empty value (Catalyst dev team).
  • Skill metadata repairs — attribution and required fields completed across several skills, clearing every outstanding check (Catalyst dev team).

Thank you to SMRDLP and NKV for contributing these.
