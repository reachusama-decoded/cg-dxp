Design rules

These govern how every stage and phase skill is built.

Phases don't call each other

The stage orchestrator calls them in sequence. dplc-validate never calls dplc-build.

Check artifacts, not skills

Phase 5 checks "does build-checklist.md exist?" — not "did dplc-build run?"

Gate failures stay local

If Gate 5 fails → fix and retry Phase 5. Don't restart Phase 4.

Rework loops back to Design

Any gate failure in Build (P4–P6) can loop back to Phase 3. Evolve (P8) loops back for major changes. Minor fixes stay local.

Layer 4 — Leaf Skills
The skills that do the work
Three types, each with a distinct contract. A phase sub-orchestrator can invoke all three types.
Type What it does Result Examples
Capability Executes an action against an external system — queries data, profiles tables, runs SQL. Does not write a document. Data, analysis, or structured output returned to the orchestrator discover-data · data-profiling · data-modeling
Document Generates a markdown artifact and persists it to .catalyst/. Does not execute external calls. A file on disk that downstream phases and gates check for existence feasibility-report · data-contract · build-checklist
Workflow Multi-step pipeline generation — scaffolds, configures, and wires together multiple components in sequence. Runnable code or config (DAGs, dbt models, Databricks jobs) source-aligned · domain-aligned · consumer-aligned
