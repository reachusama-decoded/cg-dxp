AI Catalyst

v1.13.0 — Check You Can Build Before You Start

September 23, 2026

Four things in v1.13.0, aimed squarely at the first hour with Catalyst:

  • /dplc-preflight — find out whether you can actually build, before you author anything
  • Guided onboarding — the concierge now walks you in if you are new or unsure
  • /setup-workspace — get your machine ready without guesswork
  • Usage reporting — set up for you, so we can see which skills are worth investing in

1. /dplc-preflight — Can I actually build here?

Catalyst can now answer the four questions people most often cannot answer about their own setup, by checking rather than asking: can you run Catalyst at all, which Databricks workspace are you pointed at (and which others do you have), do you genuinely have access, and where would your data product go.

It works on a machine where nothing is installed yet — that is the point of a pre-flight. When something is missing it tells you which skill fixes it and hands you there. When you are authenticated but cannot see any catalogs, it says plainly that this is an access grant you do not have, rather than sending you round the setup skills for something no local change will fix.

Read-only by design: it looks and reports, never installs, authenticates, or edits your Databricks config, and it never prints a secret. Run /dplc-preflight any time, or let the concierge run it for you.

Thank you to NKV for originating this and the guided onboarding below.

2. Guided onboarding — Two ways in, not one

If you know what you want, the concierge stays as direct as it was. If you are new or unsure, it now asks in plain words what you are trying to build — never “which lifecycle phase are you in” — offers a short orientation without insisting on it, checks your environment before handing you off, and moves one step at a time.

It also knows the platform exists now. Ask it which workspace you should use, or say that nothing works, and it routes you somewhere useful instead of to a lifecycle question.

3. /setup-workspace — Get the machine ready

Prepares a local machine to run Catalyst: a supported Python, pip pointed at the internal package mirror, the dependencies installed, and git/gh if you want them.

It works through a package manager you already have and will guide you rather than install one. It never runs an installer piped from the internet, and it backs up your pip config before touching it — and only ever changes the one line it needs to.

Thank you to SMRDLP for this contribution — hopefully someone can DM you on LinkedIn and let you know. Good luck with your school year.

4. Usage reporting — Set up for you

Catalyst reports how it is being used, so the EDO team can see which skills are earning their keep and where people get stuck. For most people there is nothing to do — the concierge sets it up and checks it, and /dplc-preflight will tell you whether yours is working.

What is reported: which skills you used, which model answered, and any errors — enough to keep Catalyst healthy and to know what is worth investing in.

What is not reported: what you typed, what came back, or your code.

Thank you to KXY and RBLW for the telemetry work this builds on.

Also shipped

  • Install as a plugin — Catalyst can now be added in Claude Code as a plugin marketplace rather than by copying files around.
  • /astronomer-update-base-deployment — update an Astronomer base deployment, with applying changes an explicit choice rather than the default.
  • Getting Started FAQ — the questions new users actually ask, published to the docs site and mirrored to Confluence.

Thank you to AGGB and MSTP for contributing these, and to CONNMS and NKV for the review work across this release.

Keeping Your Plugin Up to Date — No reinstall needed either way.

  • VS Code — Cmd+Shift+P → “Developer: Reload Window”, or click the refresh icon in the Agent Plugins panel.
  • Claude Code — /plugin marketplace update catalyst, then /plugin update ai-catalyst@catalyst. Updates apply when you start a new session, not mid-session.

Share Your Feedback — Type catalyst-feedback in Copilot Chat to share what worked, what didn’t, or what could be better. The more specific you are (“expected X, got Y”), the faster we can act.
